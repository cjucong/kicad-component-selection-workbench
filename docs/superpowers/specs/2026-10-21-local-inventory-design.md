# 本地库存与多套用量设计

## 目标

在 KiCad 器件选料工作台展示用户已购且当前可用的本地库存，支持从订单核对 Excel 导入，并按可配置套数比较库存与装配需求。

## 约束与数据来源

- 来源文件只读；导入过程不修改或搬移来源 Excel。
- 库存数据属于当前工程，默认保存到 `BOM/选料工作台/本地库存.json`，与选料记录及立创实时/缓存库存分离。
- 数据按商城 C 编码记录；只有辅助字段型号/品牌/封装/来源订单/导入时间和数量，不将采购信息写进原理图。
- 用户确认来源表的“同型号已购合计”为当前现存物料量。不得将发货数量、订单数量当作库存再累加。
- 同一 C 编码若在多条订单行重复出现且汇总数一致，只保留一条库存值，并保留来源摘要；汇总数冲突则该编码标为待核实，不自动选择较大值或累加。

## 导入和匹配

- 顶部“数据”菜单增加“导入本地库存…”；支持 `.xlsx` / `.xlsm`，选择工作表并按表头识别字段。
- 最低必需字段：商品编号/C 编码、同型号已购合计。厂家型号作为辅助信息；缺少必需字段、数量无效或冲突记录不得静默入账。
- 导入先显示预览和汇总：新增/更新/重复/待核实数量，以及各待核实项的原因；用户明确确认后才保存。
- 工作台与本地库存只按当前有效主料 C 编码精确匹配。仅型号相同但 C 编码缺失/不同的项目显示为待匹配提示，不自动把库存归到该行。
- 重复导入使用 C 编码 upsert，不叠加数量；导入文件中缺失的历史库存默认保留。用户可在预览确认更新已有数量。
- 实测来源表存在非 C 编码采购编号：这类记录按完整型号/品牌/封装保留在 `unmatched`，相同汇总不相加。支持在预览中显式指定工作台主料 C 编码后重新预览确认，未匹配时不计可用量；对应已有同编码不同数量时仍待核实。

## 工作台交互与计算

- 列表增加可在“列表视图”中隐藏/排序的“本地库存”列，保持现有列布局持久化机制。
- 单元格显示现存量、需求量、差额及状态；无匹配显示“未匹配”，零库存与未导入明确区分。
- 工具栏增加紧凑的“套数”正整数输入，默认 3，并在工作台 UI 设置中持久化。
- 需求量 = 当前行单套用量 × 套数；余量 = 本地库存 − 需求量。状态区分充足、不足、未匹配、数据待核实。
- 同一分组行沿用当前行的 `quantity`（位号数量合并后的单套需求），不按表格行数重复计算。
- 同 C 编码跨分组共享一个库存池，显示本行需求和编码合计需求；NC 不消耗，列表筛选/隐藏不改变已加载清单总需求。
- 订单表给出的位号只用于预览中的匹配建议；不能取代 C 编码作为库存身份，也不能在用户确认前变更库存映射。
- 商城库存查询/筛选和本地库存显示互不覆盖；现有“库存异常/低库存”逻辑不混用本地库存状态，除非后续单独确认扩展。

## 持久化与安全

- 新增独立本地库存数据文件，不改变现有 overrides 与 stock cache schema。
- 采用原子写入，记录 schema 版本、来源文件名、导入时间、每编码当前数量与辅助字段；不保存订单收货人、电话、地址等个人信息。
- 导入只解析必要列；错误行保留错误原因供用户复核，不把完整订单明细复制到工程数据。
- 工程外自定义数据目录应遵循现有配置，不在源码仓库写入任何采购数据。

## 验收标准

1. 可预览并导入上述订单格式；库存量取“同型号已购合计”，重复 C 编码不会被订单行数重复累加。
2. 编码冲突、数量缺失/无效、未知编码和仅型号相似的条目均有明确待处理状态，不产生错误的可用库存。
3. 同一 C 编码准确显示在工作台匹配行；需求量随“套数”即时更新且重启后套数保持。
4. 本地库存列可通过既有列表视图配置隐藏/恢复，原有商城库存及查询行为不回归。
5. 导入文件和生产工程不会被测试修改；专项单测使用合成表格及一次性工程。
