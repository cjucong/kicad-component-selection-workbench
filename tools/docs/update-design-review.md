## 保守的适用建议

以下是结合项目约束的设计判断，不是官方强制要求，也不意味着现有实现存在缺陷。保持既有窗口与设置结构，只核对更新流程所需的状态、文案和操作。

| 场景 | 建议及依据 |
| --- | --- |
| 检查 | 手动检查立即给出“正在检查”，结束后明确区分“已是最新”“发现新版本”“检查失败”；后台没有更新时保持安静。“默认仅提醒”不能解释为禁止手动检查，也不能解释为允许自动安装。[S1、S7；默认策略来自 AGENTS.md] |
| 新版本 | 显示当前版本、目标版本和对应正式 Release 的发布说明链接，再给出明确的下载或安排更新动作。不要只链接会随发布变化的“最新说明”；本项目仍以正式发布资产为准，普通代码推送不是可安装版本。[S2；发布边界来自 AGENTS.md] |
| 下载与进度 | 区分“下载”“校验”“等待关闭”“安装”，下载字节满额只代表下载结束。总字节未知时显示不确定进度或已下载量，不伪造百分比；校验阶段不要沿用“更新 100%”。进度不能抢焦点；不为检查或下载锁住整个工作台。[S3、S4、S8] |
| 用户控制 | 有能力真正终止网络传输并处理临时产物，才提供“取消下载”。只关闭面板时写“关闭”，任务继续则保留可找回的状态；不把关闭面板等同取消任务。替换程序的临界阶段不可安全中断时明确说明，不提供虚假的取消。[S4、S6；临界阶段策略为项目建议] |
| 安装与重启 | 按实际行为命名，如“关闭后安装”或“安装并重启工作台”，不能用“确定”掩盖退出。保留“稍后”安全出口；用户正常关闭前先保存编辑、确认任务可退出，再停止所属后台。不能因为下载已完成就强制退出，也不能因通用框架会关闭所有窗口就结束 KiCad 或其他工程。[S6、S7、S8；宿主边界来自 AGENTS.md] |
| 失败 | 在原更新区域保留简短错误、失败阶段和可行下一步；技术日志放到可展开或复制的详情中。网络失败可重试；校验失败应拒绝安装；占用或保存失败应说明需正常关闭哪个工作台或先完成什么操作。未知原因不编造为“网络问题”。[S5、S6；拒绝条件来自项目安全契约] |
| 重复操作 | 更新任务运行时复用同一任务状态，禁用重复提交；重试要区分仍在执行、已失败、已取消。限频时说明下次可检查时间，不把限频或缓存命中显示为更新服务失败。[S7；任务复用和限频反馈为项目建议] |

### 安全保护与易用性分开

- **不可为简化操作而取消的保护**：正式发布来源、版本与包身份校验、SHA-256、只更新程序文件、工程外备份与失败回滚、拒绝覆盖源码仓库、拒绝影响其他工程。这些是 `AGENTS.md` 的本项目要求，不是 VS Code 资料证明的通用实现。
- **签名不等于用户登录**：Tauri 的私钥属于发布流程，客户端公钥不是秘密；这不构成向使用者索取 GitHub Token、密码或读取浏览器凭据的理由。[S8] 本项目继续匿名访问公开正式发布资源；离线、限流或受限网络时提供重试或官方 Release 页面，不引入凭据流程。
- **哈希不等于独立发布者签名**：同源清单与包同时被替换时，匹配的哈希本身不能提供独立的发布者身份证明。这是信任边界分析，不声称本项目采用 Tauri 签名，也不据此扩大为本轮架构改造。
- **可改善的操作负担**：阶段可见、按钮语义、稍后处理、可行重试和错误详情。优先减少无意义确认与模态打断，不减少来源/完整性/工程隔离检查。[S3 至 S6]

## 测试目标

以下为研究阶段提出的验收目标，不代表全部已实现或已验证。实际完成项见末节。后端使用隔离临时工程和模拟发布资源；真实联网与 WebView2 冒烟单独记录，不拿生产工程测试安装。

| 目标 | 建议验收 |
| --- | --- |
| 状态契约 | 模拟无更新、有更新、超时、无网络、畸形清单和 HTTP 限流；界面明确区分结果。检查失败不显示“已是最新”；提示模式不发起安装。[S1、S7] |
| 并发与缓存 | 快速连续检查/下载仅有一个有效任务；缓存命中仍说明检查时间，手动限频给出可重试时机。取消后旧回调不得覆盖新任务；关闭再打开能恢复真实状态。[S7；并发细节为工程验收目标] |
| 真实进度 | 分块下载、未知长度、停滞、下载完成但校验未结束、校验失败：阶段正确，不能提前报告安装成功；无依据不显示剩余秒数。[S3、S4、S8] |
| 取消与稍后 | 取消在安全阶段生效且临时产物按约定处理；仅关闭面板不触发安装。稍后继续使用旧版本，按约定保留或重新获取包；不可中断阶段不会误示可取消。[S4、S6] |
| 保存与退出 | 待保存编辑、保存失败、任务忙碌、其他工程工作台运行分别阻止不安全退出/替换；明确说明下一步。安装前只退出所属宿主，保留工程数据及转换器；失败恢复后仍能使用旧版本。[S7、S8；项目契约] |
| 公开资源与完整性 | 不带 Token/Cookie 可处理模拟公开发布；缺失资产、版本不符、SHA-256 不符均拒绝安装。不因认证失败弹出凭据输入或退回未经验证的包。[项目契约，非本轮真实联网更新验证] |
| 实际交互 | 真实 WebView2 验证检查/下载不阻断正常编辑，后台进度不抢焦点；长错误、中文版本说明、缩放下按钮不遮挡。错误可关闭、可重试、详情可复制；“安装并重启”等动作与实际效果一致。[S3 至 S6] |

## 本轮落地

保持工作台现有紧凑布局，只修改更新面板及更新检查的限流等待行为：

- **已复现并修复**：更新方式保存失败后界面仍显示未保存的选择；已校验的包点击安装时重复下载；源码模式检查后提示被“已是最新”覆盖。新的真实 Chromium 测试先在旧实现复现失败，再验证修复。
- **动作分离**：发现新版后显示“下载更新”，下载并校验完成后改为“重启并更新”。保留稍后处理；自动模式下载完成不强制退出，仍在正常退出后安装。[S6 至 S8]
- **过程可见**：检查、下载/校验和设置保存期间显示不确定进度；不伪造百分比。关闭面板不取消任务，再打开继续展示当前状态。显示本次会话上次成功检查时间；发布内容以纯文本展示并可折叠。[S2 至 S6]
- **失败可恢复**：保存失败回退原更新方式，下载失败可重试，已有已校验包不因检查失败被丢弃；未保存工程设置阻止重启。
- **限流不连点请求**：HTTP 403/429 后在工程外保存等待期限，重新打开仍生效；提供可重试时间，等待不阻止修改更新方式或安装已校验包。参考响应头，缺省至少 60 秒；本项目防御性上限为 3600 秒，不宣称对超过一小时的服务端等待值原样执行。[S9]

未新增取消下载接口、真实字节进度、签名体系或强制重启，不改变正式 Release、SHA-256、源码保护、备份回滚和工程隔离要求。源码提交不等同于已发布新版本。
